# Security Policy

Please report suspected security vulnerabilities privately rather than through a normal public issue.

## Reporting a vulnerability

If the target repository has GitHub private vulnerability reporting enabled, use **Security → Report a vulnerability** in that repository.

If private vulnerability reporting is not available, use a private contact method listed by the repository owner or in repository documentation. If no private contact method is published, open a minimal public issue asking how to make a private security report. Do not include exploit details, credentials, private data, or other sensitive information in that issue.

A useful private report includes, when known:

- the affected repository, component, and version or revision;
- a clear description of the issue and potential impact;
- reliable reproduction steps or a proof of concept;
- relevant configuration or environment details; and
- any known mitigations or workarounds.

Please allow maintainers an opportunity to investigate and coordinate a fix before public disclosure.

## Supported versions

Individual repositories may define their own supported-version policy. Check the repository README, release documentation, or security guidance for the versions currently maintained.
